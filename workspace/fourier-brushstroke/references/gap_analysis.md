# 多图逐阶段误差归因：差距在哪里（2026-10-18 第二轮）

本报告回答用户问题「总结以上几种例图的成品 → 找到算法缺陷 → 修正 → 距离原图差在哪」。
方法：对 5 张例图（elf 线稿、DeepSeek logo、pale 柔光插画、chibi 彩插、horn 线稿）用同一口径
（渲染 R=1024、参考图 LANCZOS 重采样到渲染尺寸、`metrics.compare()` 同分辨率）做**逐阶段归因**，
再按 dB 头寸排序修复。脚本：`assets/out/audit/analyze_gap.py`（可复现）；渲染侧 A/B 见
`assets/out/tuning/report.md`（150 cells 独立复测）。

## 4. 差距到底在哪（结论）

1. **线稿类**：剩余误差 ~75–96% 集中在墨迹边界 0.5–2px 环。管线已能表达中心线+宽度，
   但边界仍是"栅格轮廓 + 软边"的近似；要到下一档需要亚像素轮廓（cov=0.5 marching squares）
   或严格按"中心线+解析宽度"重建。这是当前最大的可改进项。
2. **柔光插画类**：剩余误差主要在填充区内部颜色（高频/柔边被"一个区域代表色 + 低阶颜色场"平滑），
   属于表示法边界；增加颜色场网格/笔画数只能小幅回收（F5 仅 +0.2~0.25dB）。
3. **硬量化/8× 放大源**（logo 类）：填充会忠实复现阶梯块，而参考重采样会平滑 → 这类源上"中轴渲染"
   反而更接近参考；已按 AA 像素占比自动保留保守路由，避免负收益。
4. **分辨率不是瓶颈**：R=1024→2048 PSNR 不升；提高 R 只提升观感锐度与 SSIM 少许，代价是构建时间。
5. **一笔画通道**：修复填充侧表颜色场后，pale 一笔画静态 18.87→22.50dB（距逐笔画仅 0.73dB），
   视频末帧与 PNG 预览 14.5→22.9dB；剩余差异来自视频作画区分辨率（473×789 vs 614×1024），
   需要更高清用 `--size 1080x1620`。其他例图视频需重跑 onestroke+video 才带上新侧表。
