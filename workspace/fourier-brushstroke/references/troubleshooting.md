# 异常与调参手册

> 先读 `references/capability_boundary.md` 确认输入在能力范围内；
> 本文处理"能力范围内但结果不满意"的情况。
>
> 所有命令都在 skill 的 `scripts/` 目录下执行（Windows 路径用引号包住）：
>
> ```bash
> PY="<python>"
> cd fourier-brushstroke/scripts
> ```
>
> 不确定当前参数时先跑 `"$PY" fbs.py <子命令> --help`。本文命令与最终 CLI 同步维护
> （CLI 定稿：`build` / `onestroke` / `video` / `render` / `eval` / `acceptance`）。

---

## 1. 排查顺序（不要跳步）

1. **看错误码**：`E_*` 表示输入/环境问题（§2）；`W_*` 表示已降级但可产出（§3/`capability_boundary.md` §6）。
2. **看图像分类**：分类错会导致整条路径错。输出里 `image_class.klass` 与实测特征值都会打印。
3. **看四维度量**：`python scripts/fbs.py eval --fbs X.fbs.json --image 原图.png`。
   **禁止只看 PSNR 一个数**（PSNR 对线质量/渐变不敏感）。
4. **看合成用例**：能用 256×256 合成图复现的，绝不在真图上摸索（秒级 vs 十分钟级）。
5. **看是否可比**：A/B 两边的 `target_resolution`、`epsilon_px`、代码指纹必须一致（见 `engineering_guardrails.md` G2）。

## 2. 异常码表（`E_*`，与 `CONTRACT.md` §9 同步）

| 码 | 含义 | 处理 |
|---|---|---|
| `E_INPUT_MISSING` | 文件不存在 / 路径错误 | 检查路径；中文路径用引号 |
| `E_INPUT_FORMAT` | 无法识别的格式（含 SVG/PDF） | 转成 png/jpg/webp/bmp/gif/tif 再输入；矢量文件直接用 |
| `E_INPUT_CORRUPT` | 解码失败 / 文件截断 | 重新导出原图；本工具不修复损坏文件 |
| `E_INPUT_MODE` | 不支持的像素模式 | 正常应被 Stage 0 覆盖；报此错说明归一化缺口，请附原图模式 |
| `E_INPUT_TOO_SMALL` | 长边 < 32 px | 放大原图或用更大源图 |
| `E_INPUT_TRANSPARENT` | 完全透明 / 阈值下无可见像素 | 检查 alpha 通道 |
| `E_PHOTO_DEFERRED` | 判定为照片，暂缓支持（决策 D5） | 见 `capability_boundary.md` §4；先做插画化/量化；**不可绕过** |
| `E_FBS_INVALID` | `.fbs` 读取/校验失败（含旧 v1 文件） | v2 只读 v2；旧产物用新流水线重新生成；报错会指出具体字段 |
| `E_CURVE` | 曲线几何退化（点太少/全等点/弧长 0/closure 非法） | 多数情况下上层会转成 `W_GEOMETRY_SKIP` 跳过该笔画；直接报出说明该输入曲线不可参数化 |
| `E_METRIC_RESOLUTION` | 度量两边分辨率不一致 | 必须同分辨率；用 `fbs.py eval` 自动按参考图原生分辨率渲染 |
| `E_METRIC_INPUT` | 度量输入图像维度/通道非法 | 报出实际 shape；检查参考图/渲染图是否损坏 |
| `E_RENDER_RESOLUTION` | 渲染分辨率/画布/supersample 非法或超限 | 降低 `--resolution` / `--supersample` |
| `E_RENDER_MODE` | 未知渲染模式 | `--mode` 只能是 `stamp`/`sweep`/`line` |
| `E_RENDER_GEOM` | 渲染输入几何数组长度不一致（内部错误） | 属需修 bug：附完整命令、`.fbs` 与堆栈上报 |
| `E_SVG_INVALID` | SVG 自检解析失败 | SVG 不可用，但 `.fbs`/PNG 正常；可 `--no-svg` 跳过 |
| `E_CONFIG` | 配置参数非法（如 `epsilon_px` 越界、`--size` 格式错） | 按报错里的合法范围修正 |
| `E_VIDEO_DURATION` | 视频时长参数非法 | 检查 `--duration` / `--fps` |
| `E_VIDEO_BACKEND` | 视频后端不可用（`imageio` 缺失/无法 probe） | `"$PY" -m pip install imageio imageio-ffmpeg` |
| `E_VIDEO_ENCODE` | 视频编码/文件校验失败（空文件、无可解码帧、元数据非法） | 检查后端与磁盘；不产空视频 |
| `E_*`（其他） | 内部错误 | 带堆栈输出、不吞异常；把完整命令与堆栈一起上报 |

**纪律**：所有异常都带用户可读原因并以非 0 退出码结束；**绝不静默产出垃圾**。
遇到"命令成功但产物可疑"时，先查 `warnings` 字段，再用 §3 对照。

## 3. 按症状排查

### 3.1 命令跑不起来 / 找不到模块

- 确认在 skill 根目录执行（`scripts/fbs.py` 相对路径），或把根目录加入 `PYTHONPATH`；
- Windows 路径用引号包住：`"$PY" scripts/fbs.py build "<path>" -o "assets/out/演示" --resolution 1024`；
- numpy/Pillow 版本：`"$PY" -c "import numpy, PIL; print(numpy.__version__, PIL.__version__)"`。

### 3.2 输入被拒绝

| 提示 | 原因 | 处理 |
|---|---|---|
| `E_PHOTO_DEFERRED` + 实测依据 | 分类器判定照片 | 不是 bug。先插画化/色阶量化；不建议硬闯 |
| `E_INPUT_TOO_SMALL` | 长边 < 32 | 换更大图 |
| `E_INPUT_TRANSPARENT` | alpha 全透明 | 检查 alpha 阈值 `alpha_threshold`（默认 128） |
| `E_INPUT_FORMAT` | 格式不在名单 | 用 Pillow 转 PNG 后重试 |

### 3.3 分类看起来不对

- 黑白线稿被误判为彩色插画：看 `mean_saturation` 与 `edge_density`——
  **唯一色数对 JPEG 灰阶线稿失效**（抗锯齿/压缩会产生数千灰阶），必须靠饱和度区分；
- 平滑渐变被误判为照片：看 `noise_level`（渐变≈0，照片高）；
- 分类是全局策略开关：误判会导致路径错、笔画数爆炸或精度骤降。
  报告分类问题时**附上分类实测特征值**，不要只说"分错了"。

### 3.4 笔画数爆炸 / `.fbs` 体积过大

按优先级处理（每步都要复测再决定是否保留）：

1. 提高 `--denoise-sigma`（默认 0.6；0.8–1.0 抑制中轴毛刺，**代价是细节变糊**）；
2. 提高 `--min-branch-length`（短分支丢弃）；
3. 调整 `--prune-threshold` 与尖角保真开关（`corner_preserve`；关闭它会让尖角变圆）；
4. 提高 `--branch-merge-distance`（邻近端点合并）；
5. `--max-curves` 是**安全阀而非常规限制**：设宽几乎无害（只截断、不分配），
   但被截断时必须看 warning 里的丢弃数量。**不要为了体积先砍 `max-curves`**，
   那会优先砍掉天生短的"补洞笔画"。

### 3.5 填充区域被磨圆 / 尖角丢失

- 中轴（圆盘并集）的边界是凸圆弧包络，**天然无法表达凹口与尖角**；
- 正确路径：块状区域走 `region_fill`（显式 `poly` 填充）而不是纯中轴；
- 检查：区域边界追踪点数是否≈周长；`corner_preserve` 是否开启；尖角分支是否被剪枝；
- 若 `region_fill` 轮廓不闭合：**跳过该填充，不要填出碎片**（宁缺勿凑，见 `engineering_guardrails.md`）；
- **环状/空心区域不能走轮廓填充**（外轮廓填充会把洞填实，例如对话气泡、高光描边）。
  分解器会检测内部洞（`W_HOLE_REGION`）并回退中轴分支——看到该 warning 属正常降级。
- 柔光插画出现**彩虹噪点/碎斑**：先确认渲染器颜色场量纲按整场统一判断（v2 已修此 bug）；
  仍碎就 `--min-region-area 100~200` + `--denoise-sigma 0.8~1.0`。
- 区域填色边缘出现一圈偏暗的**接缝黑线/虚线**（层层叠叠）：颜色场把边界抗锯齿像素平均进网格所致。
  **已修**：颜色场单元只用区域内部像素（DT≥1px）估计、边界单元最近邻内部回填
  （`_component_color_field`）。若在旧 `.fbs` 上看到该现象，重新 `build` 即可。

### 3.5b 浅色区域没有填色 / 填色出现白洞

- 根因：背景/前景判定只按颜色距离（fg_tol 最大 24 色阶），近白的真实内容（肤色、浅高光、浅蓝衣褶）
  被当成背景剔除；调色板聚类还会把与背景差 6–24px 的真实色调簇整簇丢弃。
- **已修**：内容判定改为比背景更接近某个墨色即内容（最近色分类），调色板近背景保留门限降到 6。
  旧 `.fbs` 出现该现象时重新 `build` 即可；回归测试 `tests/test_coverage.py::TestPaleContentSurvival`。

### 3.5c 环/气泡/带孔区域填色整块消失

- 根因（旧）：轮廓填充只能画外轮廓，环状区域会把洞涂实，所以路由直接回退中轴分支 → 填色消失。
- **已修（hole-aware region_fill）**：`region_fill` 新增 `fill_holes` 洞几何；渲染端先填外轮廓，
  再逐洞用背景色挖掉（逐笔画/一笔画/视频三路径，旧 4/5 元素侧表兼容）。环状实心结构在洞显著
  （>12% 面积）且洞数 ≤64 时强制走填充。见 `W_HOLE_REGION`（info，现在表示"按带洞填充处理"）。

### 3.5d 细密排线/短笔触被丢掉

- 根因（旧）：长度 < 0.5×`min_branch_length_px` 的分支被一律丢弃（manga 实测丢 3191 条）。
- **已修**：改为按**墨量**（长度 × 中位全宽）过滤，≥2.5px² 的短笔触保留为短笔画，只丢亚像素噪声；
  `W_SHORT_BRANCHES` 分别报告保留/丢弃数量。

### 3.6 实心圆 / 圆盘区域整个消失

退化"点盘"没有长度：实心圆的中轴是单个像素。渲染器对"总长度 ≤ 0"必须有专门的
退化分支（整盘按半径画），否则区域整个消失。检查该分支是否被移除。

### 3.7 细线丢失 / 变成虚线

- 亚像素细线（宽度 0.3–0.5 px）的峰值覆盖率永远 < 0.5，**任何 50% 判决面都看不见它**；
- 正确做法是局部质量守恒掩码（逐块分位阈值），**不是全局调低阈值**
  （全局调低实测让多画从 11% 飙到 34%）；
- 二值掩码**不能直接高斯平滑**：1 px 线经 σ≈0.8 高斯后峰值 0.499，恰好被 0.5 判决面切成虚线；
- 渲染端亚像素宽度用精确带覆盖 `min(0.5, d+r) − max(−0.5, d−r)`，
  旧式 `clip(r+0.5−d)` 会把细线画胖近一倍。

### 3.8 颜色发灰 / 墨色变淡 / 腮红画不出来

- 抗锯齿过渡色合并时**不能平均颜色**（平均会让墨色变淡）；
- 区域代表色**不能只取轮廓点中位色**：柔边块用中位数会被拉回背景色，色度被抹平；
  正确做法是取腐蚀内部统计色，并在**色度轴取高分位数**（真实腮红 R−G 可达 40，
  中位数可能只剩 15）；
- 多色平涂图要**同时看掩码指标与像素指标**：掩码分不清"灰"和"黑"，
  "把灰画成黑"在结构指标里完全不可见。

### 3.9 开曲线重建出多余斜线

傅里叶级数天然周期。开曲线必须在参数化时做 **C1 连续闭环**（端点切向连续），
否则首尾跳变会产生多余斜线/尖点。检查 `closure` 字段与闭环端点断言。

### 3.10 线被画成一串点（R5 失败）

- `mode` 必须为 `sweep`（路径 ⊕ 圆盘连续扫掠）或正确间距的 `stamp`；
- 采样数必须 ∝ 路径长度（`采样数 ≈ k·弧长·R`），写死采样数会让长路径相邻采样隔几十像素，
  画出弦而不是线；
- 视频里逐帧只在"已画部分"盖印，**不能每帧重画整图**（会闪烁/低效）。

### 3.11 图上出现横穿直丝 / 抬笔处有细线

抬笔段（travel）宽度必须为 0 且渲染时**跳过**。给半径设 `max(r, 0.30)` 之类下限
会把抬笔段画成细线。检查宽度 0 分支。

### 3.12 一笔画通道：覆盖不足 / 颜色保真低

一笔画的本质限制：全部笔画串成一条路径，单次 FFT、单次连续作画。
- **几何**：路径偏差验收 ≤ 0.05 px @R=1024（用求值曲线与目标点比，不是肉眼看）；
- **覆盖**：历史上曾出现一笔画扫掠覆盖只有逐笔画 0.50×。新版必须用
  「墨线总长 × 平均宽度」标量先判断是**真丢宽度**还是**度量低估**，不要急着加密路径；
- **颜色**：一笔画颜色曲线与逐笔画同源，若保真低先查填充侧表 `one_stroke_fills`
  与颜色分块误差上限，而不是调全局参数。

### 3.13 同一 `.fbs` 在 2R 渲染出现振铃

**这是设计语义，不是 bug**：N（谐波数）的精度绑定在 `target_resolution` 上。
要 2R 清晰，请以 `render_contract.target_resolution = 2R` **重新生成** `.fbs`。

### 3.14 视频问题

| 症状 | 原因 | 处理 |
|---|---|---|
| 视频只有前一段就结束 | 步数/帧数上限写死，触发提前截断 | 检查是否 `W_VIDEO_FPS_RAISED`；上限必须由数据导出 |
| 时长不是 60 s | `--duration` 与 `--fps` 不匹配 / 帧数取整 | 时长允许 ±5%；超出检查 `--fps` 与帧数 |
| 作画步骤被跳过 | 帧数 < 作画步骤数 | 自动提高 fps 并给 `W_VIDEO_FPS_RAISED`；**不允许省略步骤**（R3） |
| 编码失败 | imageio / imageio-ffmpeg 未安装（可选依赖） | `"$PY" -m pip install imageio imageio-ffmpeg`；不影响静态 `.fbs`/PNG |
| 视频很卡 / 太慢 | 每帧重算全部系数 | 必须一次 `ifft` 预计算 + 逐帧切片（P6） |
| 中文字幕变方块 | 字体缺失 | 回退 `msyh.ttc` → 系统字体；仍失败则用英文标签 |
| 视频尺寸不对 | 未传 `--size` 时按竖版自适应 | 显式传 `--size 720x1080` 等 |
| 圆链抖动 / 闪烁（笔画很多的图） | ① 圆链曾被"整链平移到笔尖"（截断残差逐帧变化 → 整链抖）；② 步骤数 > `duration×fps` 时自动升到高 fps，u 按步骤跳变 | ① 已修：圆链按绝对坐标绘制，残差只体现在链尾细连线；② 加 `--smooth` 用平滑档（t 匀速推进、固定帧率），所有墨迹仍会画出 |
| 填充区是"整块淡入/色块先出现、笔再压过" | one_stroke 默认用显式多边形填充（`--fill-mode polygon`），填充按 t 区间整体铺开 | 用 `--fill-mode brush --order lines_first` 重新生成一笔画：填充变成宽笔一行行扫出来的笔触，且先画线稿、后铺色——画面随画笔逐步出现 |

## 4. 调参手册

> 默认值以 `scripts/fbs.py <子命令> --help` 与 `scripts/fbs_core/config.py` 的 `FBSConfig` 为准。
> 下表是**调整方向与副作用**；CLI 只暴露常用项，其余为 `FBSConfig` 内部参数（改代码/配置默认值）。
> 每次只改一个参数并复测（改了三个参数却变好，你不知道是哪个起的作用）。

### 4.1 `build`（预处理 + 分解）

| 参数 | 作用 | 调大 | 调小 | 副作用/注意 |
|---|---|---|---|---|
| `--resolution R` | 目标分辨率（长边像素）。**N 的精度锚点** | 更清晰、N 更大、文件更大、更慢 | 更快更小、细节少 | R 改变则旧产物不可比（契约不同） |
| `--denoise-sigma` | 高斯预平滑。直接决定中轴稳定度 | 抑制毛刺分支 | 保留细节 | 太大会糊掉细线；二值掩码不能直接大 σ 平滑 |
| `--colors` | 颜色分层数（0 = 自动 8–64） | 颜色更准、区域更多 | 区域更少更稳 | 过高会让笔画数爆炸 |
| `--prune-threshold` | 中轴剪枝阈值（相对局部 DT） | 更少毛刺 | 保留更多分支 | 剪枝过度会圆化尖角（`corner_preserve` 默认开） |
| `--min-branch-length` | 最短保留分支（源像素，默认 8） | 更干净、笔画更少 | 保留细节碎段 | 太大丢掉小特征 |
| `--merge-distance` | 邻近端点合并距离（源像素，默认 2.0） | 笔画更少、更连贯 | 保留更多分叉 | 太大会把平行结构粘在一起 |
| `--hybrid` | `auto`/`on`/`off`：区域轮廓填充 + 中轴混合分解 | `on` 强制块状区域走填充 | `off` 纯中轴 | 硬边/方块类内容需要填充路径 |
| `--width-mode` | `auto`（默认；复杂图→`dt`，单笔画类→`hybrid`）/ `coverage` / `dt` | 复杂密排图更稳 | — | 覆盖率积分在邻接细线处会沿法向外溢 → 线稿默认用 DT；合成宽度反演用 hybrid/coverage |
| `--width-scale` | 渲染侧宽度补偿（0=auto：线稿/扁平 0.95、插画 1.0） | 线稿实测 +0.19~+1.22dB | — | 只在渲染侧生效（不写进 doc 宽度，A7/A13 不受影响）；合成 fixture（无 image_class.evidence）不补偿 |
| `--subpixel-axis` | 亚像素中心线精修 `auto`/`on`/`off` | `on` 强制 | `off` 关闭 | 厚填充区有漂移风险，默认 auto 由尺度判据决定 |
| `--fill-soft` | 填充边界软过渡（px，0=auto） | 边界更柔 | 边界更锐 | 0=auto：线稿/扁平 0.5px、插画 2.0px（T9 实测线稿 2.0px 过大；线稿三图 +0.25~+1.17dB） |
| `--color-field-grid` | 区域颜色场网格上限（默认 32，0=关闭）：bbox 内 N×N 加权均值，渲染端双线性采样；无效单元用代表色回填 | 渐变更准、体积更大 | 体积更小 | 关闭会丢区域内部渐变（头发高光/腮红/皮肤阴影）；小区域自动缩小网格（单元边长有下限）；32 比 20 实测 +0.2dB 左右 |
| `--max-curves` | 笔画数安全阀（默认 8000） | 更少截断 | 更快但可能丢"补洞笔画" | **安全阀非常规限制**，别拿它当调参旋钮 |
| `--force-class` | 覆盖**非 photo** 分类（lineart/flat_art/illustration/gradient） | — | — | 仅排障用；photo 拒绝不可绕过 |
| `--quiet` | 减少控制台输出 | — | — | warnings 仍写入 `.fbs`，不会消失 |
| `--no-svg` | 不导出 SVG | — | — | SVG 只是互通格式，不影响 `.fbs`/PNG |

### 4.2 `build`：傅里叶参数化

| 参数 | 作用 | 调大 | 调小 | 副作用/注意 |
|---|---|---|---|---|
| `--epsilon-px` ε | 亚像素容差（默认 0.5） | N 变小、更快、更糙 | N 变大、更准、文件大 | ε/R 直接决定 N；别和旧产物跨契约比较 |
| `--N-mode` | `error_driven`（默认）/ `energy` / `fixed` | — | — | 改模式会改变 N 的语义（A3 判据依赖 error_driven） |
| `--N-max` | 单曲线谐波上限（默认 2000） | 允许更多细节 | 更快 | 到顶仍不达标 → 钳制 + `W_N_CLIPPED` |
| `--shape-mode` | 笔形：`auto`（默认）/`round`/`soft`/`marker` | — | — | auto 由柔边/等宽判据选；marker 只适合本身用记号笔画的内容 |
| `--curve-tol` | 属性曲线**相对**拟合容差（默认 0.02；宽度按 `curve_tol × max(width)` 归一，alpha 按 0..1 绝对量纲，颜色按 8bit 色阶合并） | 曲线更简、文件更小 | 更贴合 | **过小会把像素级抖动当信号**（旧版实测 0.03→0.02 是平衡点，再小宽度误差反升） |

### 4.3 `render` / `video` / `onestroke`

| 参数 | 作用 | 说明 |
|---|---|---|
| `--mode`（render/video） | `sweep`（默认，画线 R5）/ `stamp` | `build` 的 `--mode` 也控制首帧渲染模式 |
| `--supersample`（build） | 抗锯齿超采样（默认 2） | 2 通常够；调到 3/4 收益递减、耗时翻倍 |
| `--resolution`（render） | 任意渲染分辨率（长边像素） | 同一 `.fbs` 可渲染任意 R；2R 有振铃是语义不是 bug |
| `--out`（onestroke） | 一笔画输出路径，默认 `<stem>.onestroke.fbs.json` | — |
| `--harmonics`（onestroke） | 一笔画目标谐波数（默认 65536） | 受 Nyquist 钳制（`W_N_CLIPPED`）；太大只增文件不增精度 |
| `--max-fft`（onestroke） | 一笔画 FFT 采样数上限（默认 1048576） | 与路径弧长/分辨率共同决定采样 |
| `--duration` / `--fps`（video） | 视频时长（默认 60 s）/ 帧率（默认 30） | R3：60 s ±5%；帧数不足覆盖步骤时自动提高 fps |
| `--circles`（video） | 视频里可见旋转圆数量（默认 600） | **视觉上限**；笔尖位置仍用全部系数 `ifft`，不是逐帧遍历 |
| `--smooth`（video） | 平滑档开关（默认关） | 笔画数很多（步骤 > 帧数）时用：固定 `duration×fps` 帧、t 匀速推进，避免高 fps + 步进式推进的抖/闪；不保证每个微步骤独占一帧，但所有墨迹都会画出 |
| `--size`（video） | 画面尺寸 `WxH`；默认自适应竖版 720×1080 | 过大显著变慢 |

**关于 N=65536 的正确理解（R8）**：N 是"保留的谐波数"，对应 `2N+1` 个圆。
**硬性 Nyquist 上限**：一条有 m 个采样点的曲线只有 m 个不同圆可用，即 `N ≤ M/2-2`
（`M = resample_points`，默认 4096，即单曲线 N 上限 2046）。
超上限时系数会回绕重复取（旧版曾因此 PSNR 30.7 → 5.47），
新版**必须钳制 + `W_N_CLIPPED`**（不存在 `W_BEZIER_FALLBACK`，v2 无贝塞尔降级）。
一笔画的 65536 只在**合成路径的独立采样数**足够时有意义（≈ 2×弧长像素数，`max_fft` 共同决定）；
**精度来自数据质量，不来自参数规模。**

## 5. 性能说明

- **加速后端自动探测**：scipy / opencv / scikit-image 存在则走加速路径，不存在走 numpy 自实现回退；
  `.fbs` 的 `accelerators` 字段记录实际后端。**功能等价，速度不同**（EDT/高斯/连通域可差 10–50×）。
- **耗时构成**（经验排序）：Stage 0–1 分解 > 静态渲染 > 一笔画构建 > 视频编码。
  优化优先看分解与渲染，视频通常不是瓶颈（一次 ifft + 逐帧切片）。
- **排查慢点**：任何"每删一个点就全图重算""逐采样点循环""逐帧遍历系数"都属热路径违规
  （`scripts/check_hygiene.py` 会扫）。用 cProfile 定位，不要猜。
- **内存**：渲染超采样会把画布放大 `SS²` 倍；大分辨率渲染前先做内存预估，超限拒绝并提示。

## 6. 度量结果怎么读（防止被单一数字骗）

| 你看到 | 可能被掩盖的问题 | 还要看什么 |
|---|---|---|
| PSNR 不低 | 线质量差、渐变不自然、笔触感不对 | **看图**；四维度量中的结构与线宽 |
| 掩码指标漂亮 | "灰画成黑"这类色调错误完全不可见 | **色调混淆矩阵** / PSNR / MAE |
| IoU 高 | 整体偏胖/偏瘦被平均掉 | 漏画% 与多画% 要分开看 |
| `.fbs/PNG` 比值"更小" | 口径随分辨率漂移 | **必须同时报 R 与分子分母绝对值** |
| 某项验收失败但只差一点 | 可能是判据本身的前提不成立（旧版 A3 就长期假失败） | 回到 `engineering_guardrails.md` §3.6：审判据，而不是硬凑阈值 |
