# 工程护栏（改动前必读）

> **适用对象**：任何要修改 `scripts/` 下代码的人（含 agent）。
> **强制时机**：动手改任何 `.py` 之前通读一遍，改完按 §8 检查表逐项打勾。
>
> **为什么要有这一页**：上一版实现（旧 `fourier-brushstroke`）经历 30+ 次返工。
> 复盘结论是——**返工不是 30 个独立的 bug，而是 6 类根因 + 7 个坑的反复发作**。
> 逐个打补丁必然继续返工；只有按类别用结构性手段堵死，返工率才会下来。
> 本页每条规则都对应一次有实测证据的事故，不是"最佳实践"的空话。

---

## 0. 三条总则（违反其一，后面全错）

| 编号 | 总则 | 操作化定义 |
|---|---|---|
| **Z1** | **先量化，再动手** | 任何判断必须先给出数字。"应该是 X"、"看起来更好"都不是证据。 |
| **Z2** | **不做未验证的改动** | 改完必须能给出「改前 / 改后」同口径对比。没有余量验证就不要改，并明说"没做"。 |
| **Z3** | **明确区分「已验证」与「不可验证」** | 禁止把推测写成结论。文档与报告中的"已实现/已验证"必须能对应到代码或验收项，否则标注"未验证/不承诺"。 |

## 1. 根因 G1：度量口径不唯一 → 所有归因都错（最高频、破坏力最大）

### 1.1 历史事故（旧版实测，非 v2 指标）

| 事故 | 当时的表现 | 真实情况 |
|---|---|---|
| 用「渲染色 == 底色」判漏画 | 报"覆盖率 99.1%" | 真实漏画 **8.20%**（只统计了完全等于底色的像素） |
| 重建图分辨率 ≠ 原图时先上采样再比 | "已画出的细线被判成漏画" | 上采样把细线峰值摊薄，纯粹是度量伪影 |
| 按连通域**面积**分箱归因 | 结论是"62% 漏画在大块里" | 「200px 长 × 1.5px 宽的缺发丝」被算进大块；按**厚度**分箱后 52% 是 1.75–2.5px 的发丝 |
| 墨迹掩码只分「墨 / 背景」 | 掩码指标一片漂亮 | **把灰画成黑完全看不见**；必须同时看色调混淆矩阵 |
| 区域覆盖率用 `thresh=0.10` | 覆盖 99.15%，与肉眼观感矛盾 | 极淡笔画也算"已覆盖"；覆盖判定阈值默认 **0.5** |
| 拿特性存在前的旧产物当基线 | 假的 "−4.5 dB 严重回归"，白排查 17 分钟 | 产物不同代，不可比 |
| 拿 R=512 的 A/B 产物当 R=1024 基线 | 假的"N 中位 2→11 严重膨胀" | `thr = epsilon_px / R` 不同，N 自然不同 |
| 把 `.fbs/PNG` 当"表示效率" | 同一份表示 R=512 时 **5.49×**、R=1024 时 **3.12×** | 比值随分辨率漂移，度量的是"PNG 有多好压" |

### 1.2 硬规则

- **R1.1 唯一口径**：任何质量结论必须来自 `scripts/fbs_core/metrics.py` 的 `compare()` 四维输出：
  **结构**（墨迹 IoU / 漏画% / 多画%）、**厚度谱**（按 EDT 峰值分箱）、**色调**（混淆矩阵/色差）、**线宽**（宽度分布）。
  **四维缺一不可**——结构对了可能色调全错（多色平涂图就是这样）。
- **R1.2 禁止自建临时指标**。需要新指标 → 先加进 `metrics.py` 并补测试，再使用。
- **R1.3 覆盖判定的阈值下限是 0.5**。低于 0.5 的覆盖率不得算"已覆盖"。
- **R1.4 墨迹比对必须结构比对**：不能用"颜色等于底色"这种逐像素相等判据。
- **R1.5 报告必须带口径**：任何"更好/更差/更大/更小"的数字，同时给出 R、`epsilon_px`、分子分母的绝对值。

### 1.3 自检

```bash
PY="<python>"
# 任何 A/B 结论，先问：两边的 resolution / epsilon_px / 代码指纹是否一致？
# 度量必须同分辨率（不加 --render 时自动按参考图原生分辨率渲染）：
"$PY" scripts/fbs.py eval --fbs A.fbs.json --reference ref.png
```

## 2. 根因 G2：可比性被破坏 → 假回归、假优化（两次"白排查"的来源）

### 2.1 硬规则

- **R2.1 同分辨率强校验**：渲染图与参考图分辨率不一致时**直接拒绝比较**（抛错），
  **绝不允许先上采样再比**。`.fbs` 是分辨率无关的，正确做法是把它**按原图原生分辨率**重新渲染。
- **R2.2 同契约**：两边 `render_contract.target_resolution` 与 `epsilon_px` 任一不同，不可比。
- **R2.3 同代码代**：比较前核对 `fingerprint(doc)` / `same_generation(a,b)`。
  产物字段（如 `color_fields` 是否为空、`brush_styles` 是否存在、笔画数、`region_count`）不同即视为不同代。
- **R2.4 契约不一致宁可跳过**：尺寸不同、"不同代"时**跳过并记录**，不产出数字。宁缺勿凑同样适用于度量。

### 2.2 记忆锚点

> 两次假回归（一次假 −4.5 dB、一次假 N 膨胀）都源于"拿不可比的两份产物当 A/B"。
> **比之前先证明可比**，这一步不能省。

## 3. 根因 G3：用单一全局标量代表局部结构 → 必然在某类形状上翻车

### 3.1 历史事故

| 事故 | 结果 |
|---|---|
| 填充分流按图像类别 → 按紧致度 → 按蔓延度（改三版） | 前两版都分不开"细线稿"与"填色插画" |
| 统一降低判决阈值 | 多画从 11% 飙到 **34%** |
| 颜色-only 的 AA 过渡色判据 | 256 个调色板簇塌成 **1 个**，灰发被并成纯黑 |
| 全局 `max_curves` 按长度截断 | 把**补洞笔画**（天生短）整批砍掉，残差原样留下 |
| 固定 12×12 色场网格 / 环形区域轮廓填充 | 前者边界插值拖入无效单元；后者把整个人物涂成一片灰 |
| 全局"中轴去振荡"容差 | T1 线稿 +0.025 dB，T3 平涂 **−0.43 dB**；全局容差是 R2 类错误，已复现两次 |
| 用"每档必须 2×"这类单标量判据代理一条曲线 | 局部指数在 1.17–2.4 间切换 → A3 长期**假失败** |

### 3.2 硬规则

- **R3.1 阈值的量纲必须来自局部尺度**：涉及距离/宽度的阈值写成 `k · epsilon_px / R` 或
  `k · 局部笔画宽度`，**禁止**写成绝对像素常量。
- **R3.2 二值化必须"局部质量守恒"**：逐块解出使局部面积等于局部墨量的阈值，
  而不是把全局阈值统一调低/调高。
- **R3.3 决策要带空间证据**：判断"这个颜色是真实色调还是抗锯齿过渡色"必须看**该色自身是否成片**
  （如自标签腐蚀后是否存活），不能只看颜色相似度——纯颜色判据有原理性盲区。
- **R3.4 分箱/归类按结构量而非面积**：归因漏画必须按**厚度谱**（EDT 峰值）分箱。
- **R3.5 新增/修改一条判据，必须补一个形状类别测试**：新的判据要在合成真值上分别验证
  「细（r<1）」「粗（r≥1）」「尖角」「平行结构」「环形」等类别。
- **R3.6 判据本身也要被审**：凡把一条曲线压成一个数的断言（倍率、中位数、全局比值），
  先问它依赖哪个未证明的前提。

## 4. 根因 G4：静默失败 / 无声覆盖（最阴的一类）

### 4.1 历史事故

- 三处裸 `except` 吞掉 `NameError`；
- `getattr(cfg,'x',12) or 12` 吞掉 **0**（`color_field_grid=0` 关不掉颜色场）；
- **CLI argparse 默认值无声覆盖 config 默认值**（把 `max_curves` 从 8000 打回 2000）；
- Nyquist 越界未夹 → 系数回绕重复取，PSNR 30.7 → **5.47**；
- 色场无效单元把垃圾拖进双线性插值 → 19.8 → **11.2**；
- 函数内部步数上限写死（`guard < 20000`）→ 一笔画只画出前 42%，**静默**丢掉下半身。

### 4.2 硬规则

- **R4.1 单一配置来源**：CLI 默认值一律 `None`，只在显式给出时覆盖配置文件；`0` / `False` 是合法值，不得被 `or` 吞掉。
- **R4.2 禁止裸 `except` / `except: pass`**。捕获必须指定异常类型、记录上下文、转为明确错误或 warning。
- **R4.3 任何降级都进 `warnings`**：`W_*` 码 + 可读原因，不允许只 `print`。
- **R4.4 上限/保护常量必须由数据导出**：步数、采样数、循环次数写成
  `ceil(路径长度 / 步长)` 之类，**禁止**写死；被上限截断时必须告警（"因 X 上限截断 N 个"）。
- **R4.5 精度越界必须钳制并告警**：N > `M/2-2`（Nyquist）时钳制，绝不回绕；
  `N` 或分辨率超限时写 warning。
- **R4.6 退化输入必须显式处理**：纯色、全透明、零长度笔画、空笔画、损坏文件——
  要么明确拒绝（非 0 退出码 + 原因），要么走专门路径并告警，**不许静默产出垃圾**。
- **R4.7 静态守卫**：`scripts/check_hygiene.py` 扫描裸 except、`or <数字>`、手写小数位、
  CLI 非 None 默认值、热路径逐点循环；`--strict` 下无新增命中。
  检查器误报太多就会被忽略（那样连真问题一起漏），因此需要 `# noqa` 白名单机制。

## 5. 根因 G5：热路径上的逐点 Python 循环

### 5.1 历史事故

- `clean_skeleton` 每删一个候选点就全图 `label_components` → 单图数分钟；
- 覆盖率积分的连接性掩码写成逐采样点循环 → 单图从 209s 拖到 **10 分钟以上**；
- `measure_brush` 里现算三通道投影 → 慢一个数量级；
- 视频逐帧遍历 N=65536 的全部系数 → 约 **164 亿次**运算，跑几小时
  （改为**一次 `ifft` 预计算 + 逐帧切片**后，几小时 → 117s）。

### 5.2 硬规则

- **R5.1 热路径禁止逐点 Python 循环**：内层循环交给 numpy 向量化/广播；
  仅在"每条笔画一次""每帧一次"这一级允许 Python 循环。
- **R5.2 向量化范式**：累积与用 `np.logical_and.accumulate`，分段最大用 `np.maximum.at`，
  同标签腐蚀用位移比对，邻域查找表用预计算。
- **R5.3 全图操作禁止按元素重复**：连通域/距离变换这类 O(HW) 操作，每张图只做常数次；
  多区域处理必须**按包围盒裁切**后在局部坐标做。
- **R5.4 性能预算是验收项**：改动后必须报告单图耗时（Stage 0–1、渲染、一笔画、视频），
  并与《需求追溯》中的预算对比；劣化超过 20% 必须解释。

## 6. 根因 G6：序列化与契约脱钩（冗余重发 + 凭手感定精度）

### 6.1 历史事故（旧版定位）

| 现象 | 量化证据 | 为什么当时看不出来 |
|---|---|---|
| brush 外观属性逐笔全量重发 | `shape` 只有 2 个取值却占 8.4 KB；`alpha` 只有 1 个取值占 3.1 KB | 每次只看到"文件大了 %"，归因到"笔画变多了" |
| 数值精度凭手感写死 7 位小数 | 契约 `epsilon_px/R` @1024 只需 **4–6 位**；`0.0292969` 其实是 `15/512` | 精度"更细"看起来无害，实际纯浪费字节 |
| 默认值也逐笔写出 | `repr`/`mirrored`/`fill_role` 默认值共约 2.2 KB | "总得有"的直觉 |

> 关键：这三条都**不是几何或质量回归**——同一轮 PSNR 反而涨了 0.048 dB。
> 靠"看图"永远找不到，必须靠**体积归因（逐字段计字节）+ 共享度统计（唯一值个数）**。

### 6.2 硬规则

- **R6.1 精度由契约反推**：写入小数位由 `render_contract`（`epsilon_px`、`target_resolution`）
  计算得出，**禁止手写 6–9 位小数**。系数舍入上界：第 k 个系数误差 `|δ_k| ≤ 0.5·10^-nd`，
  曲线总偏差 `|Σδ_k e^{iθ}| ≤ Σ|δ_k|`，令其 ≤ `epsilon_px/2` 个渲染像素后解出 `nd`。
  **注意标量个数是 `2·(2N+1)`**（复数的 re/im 各算一个，少算这个 2 会让上界被低估一半）。
- **R6.2 共享表 + 索引**：任何会被多笔共享的属性必须进共享表（`brush_styles` 等）并按索引引用；
  **只做精确去重（浮点全等才共享），不做有损合并**。
- **R6.3 唯一出入口读属性**：`resolve_brush()` / `set_stroke_width()` / `build_style_table()`
  之类的函数是唯一访问路径；禁止在渲染/视频代码里直接读 `stroke['brush']` 的原始字段
  （旧版 v2 文件里直读 `.get("shape")` 得到 `None` → 静默回退默认笔刷，画面变样却不报错）。
- **R6.4 格式变更加法是硬约束**：新增字段不得破坏既有读者；`poly`、`one_stroke_fills`、
  `brush_styles` 都是这么加的。改字段语义必须升 `version`，并补"新旧解析等价"测试。
- **R6.5 序列化必须有性质测试**：精度往返上界、位数单调性、系数 L1 上界、
  v1/v2 解析等价、建表无损、同内容两种写法渲染逐位相同。

## 7. 七个坑（重犯会白烧一整轮）

| # | 坑 | 现象/代价 | 硬规则（新版必须这样写） |
|---|---|---|---|
| P1 | 步数上限写死 `guard < 20000` | 一笔画只画前 42%，**静默**丢下半身 | 步数 `= ceil(轨迹弧长 / 目标步长)`，与路径长度/分辨率挂钩；触顶必须告警 |
| P2 | 轨迹采样数写死 200 点 | 长路径相邻采样隔 95px，画出长直线**弦** | 采样数 ∝ 路径长度（`_render_samples = k·arc·R`），长路径自动加密 |
| P3 | `_pack_bezier` 对闭合曲线不闭环 | 填充用直弦收口，填出直边碎片 | 填充轮廓**用显式 `poly`**，不依赖有损重建；闭合性单独断言 |
| P4 | 区域代表色取**轮廓点中位色** | 色度被拉平，肤色/腮红丢失（真实腮红 R−G=40，调色板只剩 15） | 取**腐蚀内部**统计色；色度轴取**高分位数**而非中位数（柔边块用中位数必被拉回背景色） |
| P5 | 扫掠给半径设 `max(r, 0.30)` 下限 | 宽度为 0 的抬笔段被画成细线，图上横穿直丝 | **抬笔段 `width=0` 必须跳过**，禁止任何半径下限（亚像素宽用精确带覆盖，不用下限兜底） |
| P6 | `curve_points` 逐帧遍历全部系数 | N=65536 时约 164 亿次，跑几小时 | **一次 `ifft` 预计算 + 逐帧切片**；视频只对"每帧"这一级循环 |
| P7 | 跨分辨率比对（630px 画布 vs 1024px 参考） | 得出荒谬 PSNR，结论全错 | 最终帧对比**必须同分辨率**；尺寸不同宁可跳过（见 G2） |

## 8. 改动前检查表（每次都走，不许跳）

1. **先存基线**：跑 `scripts/run_acceptance.py --quick`，记录通过/失败清单与关键数字。
   *不存基线不许改*——有事故就是因为没有同代基线白排查 17 分钟。
2. **顺序不许颠倒**：**先建度量 → 再归因 → 最后改算法**。直接改算法等于在错误坐标上优化。
3. **四维报告**：用 `metrics.compare()` 出「结构 / 厚度谱 / 色调 / 线宽」，缺一维不下结论。
4. **同分辨率、同契约、同代码代**：任何对比都要先核 `target_resolution`、`epsilon_px`、`fingerprint`。
5. **合成用例优先**：能用 256×256 合成图复现的，绝不在 200 万像素真图上摸索
   （秒级 vs 十分钟级）。`tests/gen_fixtures.py`（T1–T13）就是为此存在的。
6. **假设证伪必须回退**：被实测否掉的改法必须回退，并在代码注释/文档记下结论，
   不能留在代码里当"也许有用"。
7. **收尾三连**（在 skill 根目录执行）：
   ```bash
   PY="<python>"
   "$PY" scripts/run_acceptance.py --quick    # MUST 项不掉
   "$PY" scripts/check_hygiene.py --strict    # 无新增命中
   "$PY" -m unittest discover -s tests        # 全绿，或明确记录"既红项"
   ```
8. **格式变更**：走 additive 路径 + 升版本 + 新旧解析等价测试。
9. **更新文档**：改了行为/参数/警告码，同步 `SKILL.md`、`references/*`、`requirements_traceability.md`。

## 9. 红线清单（违反即拒绝合入）

- ❌ 用自建临时指标下结论，或绕过 `metrics.compare()`。
- ❌ 跨分辨率/跨契约/跨代码代比较（含"先上采样再比"）。
- ❌ 裸 `except`、`except: pass`、`or <数字>` 吞掉 0/False。
- ❌ 把上限、阈值、采样数写成与数据无关的硬编码常量。
- ❌ 静默降级：不写 warning、不告警、不报错。
- ❌ 热路径逐点 Python 循环，或每帧遍历全部傅里叶系数。
- ❌ 手写 6–9 位小数的序列化精度（必须由契约反推）。
- ❌ 破坏既有格式的变更（非 additive）。
- ❌ 把推测写成"已验证"，把未实测写成"已实现"。
- ❌ 为让某个功能"生效"而削弱保护性判据（旧版 `dev ≤ 0.35` 的接受闸门就是正确保护，削弱它会让端到端变差）。
